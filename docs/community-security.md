# 社区防刷与账户管理

## 用户入口

- 批注心形按钮支持点赞和取消，再次打开文章保留自己的点赞状态。
- 登录页「忘记密码」通过绑定且已验证的邮箱重置密码，沿用后端 SMTP 配置，不需要新增发信密钥。
- 管理员从「审核管理 → 用户管理」封禁或解封普通账户，必须填写原因。不能封禁自己或其他管理员。
- 「审核管理 → 操作日志」记录审核、删除、恢复、创建条目/分类以及封禁操作的管理员 ID、目标、时间和结果；不记录请求正文、邮箱、密码、验证码或 Cookie。

## 服务端约束

- 点赞采用用户与批注的联合主键，POST 幂等点赞、DELETE 幂等取消，事务锁保证并发计数一致。
- 旧版累计点赞没有用户归属，不能可靠迁移为真实票。首次点赞或取消时，该批注的计数按新点赞表重新计算，不把旧演示/重复票伪装成真实用户票。
- 评论、批注及批注回复共享每账号 10 分钟 20 次成功发布额度；同类型、同目标、相同内容（合并空白）在 10 分钟内返回 409。额度、去重记录与正文同事务写入，失败不扣额；记录存数据库，重启不清零，多实例共享。管理员也受限制。
- 用户封禁会撤销全部会话；每次认证检查封禁状态。解封不会恢复原会话。
- 重置验证码与注册验证码分表，随机 6 位，仅存 bcrypt 哈希，10 分钟有效、最多 5 次错误尝试，每邮箱 60 秒冷却、每小时最多发送 5 次；请求同时受现有 IP 验证接口限频。
- 密码重置原子消费验证码、更新密码并撤销全部旧会话。封禁账户无法通过找回密码绕过封禁。未知邮箱返回统一提示，不发送邮件；发信失败不激活验证码。没有已验证邮箱的旧账户需由运营人员核实身份后处理，不能自助找回。
- 管理员变更前先记录操作尝试；日志写入失败则拒绝操作。状态 0 代表执行中或结果未确认（如进程中断/最终日志更新失败），不能当作成功；日志是应用内审计，不是防数据库管理员篡改的外部审计系统。

## 启用与验证

重启更新后的后端时，现有 `model.Migrate` 会创建 `annotation_likes`、`community_submissions`、`password_resets`、`admin_audits` 表，并为用户增加 `banned` 字段。生产环境应先做私有数据库备份，再按现有部署流程升级。不会导出或提交这些私有数据到公开知识库。

测试覆盖点赞去重/取消、发布重复与持久限额、权限隔离、封禁会话失效及解封、操作日志、验证码分离/过期/失败次数/单次消费和密码更新。SMTP 测试使用替身，不会发真实邮件；正式部署还需验证实际 SMTP 投递。
