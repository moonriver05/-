# 管理员授权与撤销

## 使用入口

以管理员登录，打开“审核管理 → 账户管理”，按完整账号或昵称查找目标。

- 普通正常账户显示“授予管理员”；输入 1-200 字原因，再确认目标与权限范围。
- 其他管理员显示“撤销管理员”，可按同样流程恢复普通身份。
- 当前账户没有自我角色变更按钮；后端也拒绝，避免误取消唯一管理员。
- 封禁账户必须先解封，未设置登录身份的演示账户不能被提升。
- 身份变化后目标所有现有会话失效，需重新登录；重复设置相同角色是可审计无操作，不再次退出用户。

管理员能审核、删除恢复内容、管理账户及授权他人，只授予可信账户。原因进入审计。普通用户不能调用接口或修改个人资料自我升级。

## 实现与验证

接口 `PATCH /api/v1/admin/users/:id/role`，仅管理员可用。请求为 role（admin / learner）与 reason，请求体最多 4 KiB；不能从请求指定操作者。

事务中按 ID 排序锁定操作者与目标，再校验操作者当前仍为未封禁管理员；角色、目标会话删除、审计原因和动作一起提交。审计不可写时角色变更回滚。并发撤销不能只信任请求开始时的身份快照。

测试覆盖匿名 / 普通用户、非法角色、原因、自己、封禁目标、不可登录目标、授权撤销、旧会话、重复无操作、审计失败回滚和操作者中途失权。MySQL 并发语义依赖数据库事务；自动测试主要用 SQLite，不冒充生产压测。

首次管理员仍由命令行设置；网页功能只供已有管理员使用，不提供默认管理员或公开提权入口。
