# 01 项目概述与阅读导航

## 1.1 问题与定位

数学与算法词条往往定义严谨、前置知识多。初学者即使搜索到文章，也难以判断从何理解；独立聊天工具又容易脱离词条语境，使“看文章、问问题、核对答案”分散在不同界面。

MathWiki Lab 将知识阅读、AI 分层解释、连续追问和针对原句的讨论合并到一个工作区。项目目标是降低理解门槛并让回答有可检查的来源，而不是替代教材、教师或形式化证明系统。

## 1.2 当前成果

公开内容库包含 5,000 篇中文词条和 48,845 个可见章节。生产向量库已完成 48,560 个有效正文片段的建库。两种数量统计对象不同，不能相互当作覆盖率分母。

已实现标题搜索、结构化正文、四档程度与四种解释方式、SSE 流式生成、对话追问、公开原文回查、批注评论、账户与审核、H5 工作区。语音和 Elasticsearch 保留可选适配，当前生产演示未启用。

# 02 需求分析

## 2.1 角色与场景

| 角色 | 主要诉求 | 验收方式 |
| --- | --- | --- |
| 访客 | 找到条目并读懂结构 | 可检索、阅读、查看公开讨论 |
| 学习者 | 按程度解释、追问、核对 | 有分层回答、引用和原文跳转 |
| 社区参与者 | 针对具体原句交流 | 选句批注、回复、处理结果 |
| 管理员 | 控制内容与账户质量 | 审核、回收站、反馈和操作记录 |

## 2.2 功能需求

- 阅读：显示章节、公式、表格、图片与来源；复杂模板明确提示，不假装完整解析。
- 检索：标题搜索与阅读分离操作，不因输入搜索词就清空当前对话。
- AI：当前文章语境、多轮追问、可中止的流式展示、原文证据与失败提示。
- 个性化：按小学生、高中生、本科生、专业学习者调整语言，并支持生活类比、直觉与严谨、公式推导、例题演示。
- 社区：账户隔离、收藏、批注、回复、反馈、审核与恢复。

## 2.3 非功能需求与限制

有限资源：生产主机约 2 核、1.8 GiB 内存，避免额外部署本地大模型。可解释性：用户能看到引文与出处。可恢复性：建库幂等、卷持久化、失败回退。可维护性：前后端类型检查、模块边界和自动化测试。

尚未形成大样本教学效果或多人并发评价，因此不报告虚构的准确率、满意度和吞吐量。

# 03 系统架构设计

[[architecture]]

## 3.1 模块职责

Vue 负责搜索、阅读、对话、审核等交互；Nginx 统一静态资源与同源 API。Go API 承担账户权限、内容审核、原文查询、RAG 编排和流式输出。GORM 对接正式 MySQL，SQLite 只用于开发和自动测试。

Chroma 保存向量及少量定位元数据，MySQL 保留权威原文与业务状态。embedding 与语言生成通过不同云端接口完成，密钥均在服务端。

## 3.2 依赖隔离

mail、storage、search、speech 为独立适配器。未配置模型时返回明确标记的演示解释；RAG 不可用时基于当前词条回退；ES 默认不启用。当前架构没有 LangChain 或自训练模型，不应将团队过去的经验写成本项目依赖。

# 04 数据设计与代码结构

## 4.1 主要实体

| 实体 | 关键职责 |
| --- | --- |
| Article / Section | 标题、分类、来源、许可、章节位置和公开状态 |
| User / Session | 身份、角色、禁用状态与会话摘要 |
| Annotation / Comment | 原句批注、回复和审核状态 |
| Favorite / ReadingHistory | 个人收藏与阅读记录 |
| ExplanationRecord / Feedback | AI 答案记录和反馈 |
| AdminAudit | 管理操作审计 |

公开内容导出采用字段白名单，不因数据库模型增加字段而悄悄发布账户信息。分片清单记录数量与 SHA-256，导入前校验，已有内容时拒绝覆盖。

## 4.2 代码组织

backend/cmd 编排启动、导入与索引工具；internal/api 管理业务与权限；internal/ai 负责模型协议与教学约束；internal/rag 负责向量、分块、原文校验；internal/model 定义数据模型。前端按 API、工作区组件、流式解析、媒体清洗及测试拆分。

Go 使用 gofmt 和 go vet，前端使用 TypeScript / vue-tsc 与锁定依赖。关键注释说明信任边界、取消释放和失败回退原因；避免无效的逐行释义。

## 4.3 内容许可

文章保留中文维基百科来源、修订信息和 CC BY-SA 4.0 标识。图片许可依原文件页；内容改编保留来源和修改说明。代码公开评审不自动改变第三方内容许可，也不等于项目代码已选择开源许可证。

# 05 AI 技术选型理由与集成

| 方案 | 采用理由 | 代价与边界 |
| --- | --- | --- |
| DeepSeek 云 API | 避免本地模型权重，兼容 HTTP 接口、支持流式 | 网络和费用依赖；生成有不确定性 |
| 豆包 embedding | 中文语义与云端计算；现配置固定 1024 维 | 不同于生成模型密钥；索引版本必须一致 |
| Chroma | 轻量 REST 接入、持久化、可限制容器资源 | 内存随向量与索引增长，磁盘持久化不等于零内存 |
| MySQL 原文库 | 同时满足内容、权限、来源与业务存储 | 查询与审核状态需保持一致 |

## 5.1 具体配置

生成配置由 LLM_BASE_URL、LLM_API_KEY、LLM_MODEL 控制；代码当前默认模型标识为 deepseek-flash，不宣称始终为官网最新型号。embedding 使用 doubao-embedding-vision-251215 的纯文本输入，固定 1024 维，维度与模型记入集合元数据。

## 5.2 为什么不自训练或本地部署

本项目价值在知识与教学流程集成。当前资源无法合理承担大模型本地推理与训练；使用云 API 使主机主要承载业务和检索。普通词条搜索采用 MySQL 标题检索，避免在同机同时运行 ES 的额外内存需求。

选型是现有约束下的工程权衡，不是模型能力排名或唯一最优结论。模型可用性、价格和区域以实际开通账户为准。

# 06 RAG 离线建库实现

## 6.1 数据流

公开中文条目筛选 → 章节内容前缀读取 → 800 字片段与 100 字重叠 → 云端 embedding → 向量归一化 → Chroma 写入。

每章最多处理前 12,000 字，以限制单次读取和费用。规划工具按同一规则统计，当前估计 5,000 篇、41,649 个有效章节、48,560 个片段；5 个章节触及截取上限，不把这些尾部称为已完整覆盖。

## 6.2 幂等与一致性

片段 ID 结合章节 ID、片段位置，以及标题、章节标题与内容的摘要。建库前查询已有 ID，相同内容不重复调用 embedding；中断后可以重新扫描并跳过已完成片段。处理数量包含复用项，新增数量才表示本轮新写入。

Chroma 仅保存向量和 article_id、section_id 等定位信息，正文仍从 MySQL 读取。集合校验模型、维度和切分格式，避免混写不同向量空间。当前不自动删除全部旧向量，因此内容更新后的过期项需要后续维护；在线回查会拒绝不匹配的旧内容。

## 6.3 容量与费用控制

48,560 × 1024 × 4 字节约为 189.7 MiB 原始向量，仅是下界，未包含图索引、运行时、缓存和查询开销。先用 -plan 无云调用估算，再 coverage 扩大词条覆盖，最后在记录预算和资源观测下扩正文。

建库使用小批请求与间隔，索引器 GOMEMLIMIT 辅助控制 Go 堆目标，但不是严格进程内存上限；Chroma 使用容器硬限制。后台运行保留日志，避免终端断开导致任务退出。

# 07 在线知识检索与证据选择

[[rag-flow]]

## 7.1 检索策略

问题附上当前标题进行 embedding；带“第二步、它、没听懂”等指代时，附最近两轮用户问题（各最多 400 字）及上一回答（最多 1600 字），不额外调用大模型改写。独立问题默认保持自身主题。

先查当前词条候选，再查全库候选；使用余弦距离阈值 0.65，过滤并去重，最多向模型提供 5 段证据。该阈值是当前策略，尚未基于标准标注集完成最优性评估。

## 7.2 原文回查与降级

检索后重新读取 MySQL 当前公开章节，排除隐藏、删除、未发布、待审或驳回内容，并重新验证片段摘要。过期向量不能绕过公开状态。证据不可用、超时、并发满或无相关结果时，退回当前词条有限片段并显示回退状态。

指代规则不是完整语义理解；省略过多或指向很早历史时可能检索不准。下一步应以固定问题集测量相关性，而不是盲目放宽阈值。

# 08 流式生成、模型自检与引用验证

## 8.1 双阶段生成

第一阶段输入本轮问题、有限历史、教学要求与检索证据，使用 SSE 逐段发送初稿。第二阶段再次调用模型，对事实、前提、推理与引用进行自检，输出结构化 summary、steps、citations 和 checks；最终替换初稿。

这种设计改善开始等待的感受，也使最终答案能够结构化显示；代价是一次回答有两轮生成调用，自检会增加完成时间。用户可停止生成，取消信号传递给后端与上游请求；停止后不能把未完成初稿标成核验成功。

## 8.2 服务器端引用检查

引用必须包含有效 S 编号以及在对应证据中精确出现的短句。来源文章 ID、slug 和章节 ID 由后端回填，不信任模型生成的定位信息。没有有效引文的知识性最终答案会被拒绝，界面显示未完成，不伪装成功。

## 8.3 明确的能力边界

原文精确匹配只证明引文存在；它不能证明每一句结论均得到支持，更不能代替数学形式化验证。第二轮仍是同类生成模型，可能重复错误；confidence 不是经校准的正确率，当前界面使用“模型自检完成”而非“数学证明通过”。

普通感谢、寒暄和结束对话无需硬套数学推导或编造引文。用户历史和词条文本都不应被当作系统指令或独立事实证据。

# 09 个性化教学与连续追问

## 9.1 表达偏好优先级

本轮明确要求的读者程度、语言难度、篇幅和解释方式，优先于下拉框默认值；历史回答的风格不覆盖本轮选择。优先级只影响讲法，不改变事实与引用规则。

小学生：从可观察情景出发，短句解释新术语；高中生：连接中学代数几何；本科生：补足关键定义与推理；专业学习者：关注前提、形式化定义、边界与条件。

生活类比说明对象对应和局限；直觉与严谨分开动机和结论；公式推导先解释符号；例题演示给小而完整的条件、过程与检查。不适合推导的简单问题不强行编造公式。

## 9.2 双阶段一致性

生成和自检共享表达要求；同步接口的自检也保留用户原问题。用户说“没听懂”时要求换情景、降术语密度，不只是把原句略缩短。引文可保留专业原句，讲解仍应符合读者程度。

## 9.3 现阶段结果与限制

用户提供的像素偏移截图出现了方格纸类比、分步骤说明和类比局限，说明模式能影响真实回答；摘要仍偏长，不能据单个例子断言教学效果显著。自动测试验证要求正确传递，不能验证模型每次均遵守。

对话历史最多保留近期 6 轮、总字符预算 32,000；刷新恢复和长期学习画像仍属于后续改进。追问检索使用规则补上下文，避免再增加一次模型请求的费用与延迟。

# 11 安全、资源与费用控制

## 11.1 身份与内容边界

会话使用随机 Cookie，数据库保存其摘要；密码使用 bcrypt，管理员权限从服务端读取。写请求同源校验，注册必须邮箱验证。公开导出不含账户、密码哈希、批注、收藏、反馈或对话数据。

密钥只在后端，VITE_ 变量不能放凭据。输入 HTML、媒体 URL 和公式链接须清洗。RAG 的在线回查阻止过期隐藏内容从旧索引重新公开。

## 11.2 本轮 AI 准入保护

同步和流式端点共享限额：每账户同时一条，默认全局最多两条，每账户一分钟最多六次准入；配置分别为 AI_MAX_CONCURRENT 和 AI_REQUESTS_PER_MINUTE。拒绝发生在检索和模型调用之前，返回 429 / 503 与 Retry-After。

错误、取消和异常均释放并发占用；已准入但失败仍消耗窗口计数。记录过期回收并有总量上限。该方案只适用单 API 实例，进程重启会重置，不能充当充值余额或多实例分布式限额。

## 11.3 网络与部署

MySQL、Chroma 仅本机访问；正式对外服务应使用 TLS 与安全 Cookie。当前生产 HTTP 是已知部署限制，不能在文档中宣称传输已加密。Chroma 卷应备份并验证恢复，镜像摘要固定；重启策略避免宿主重启后服务忘记启动。

历史 PHP 安全通知经进程、目录与容器检查未发现对应运行服务；这不是全机安全审计结论，操作系统更新需独立维护。

# 14 技术创新点与应用创新点

## 14.1 技术创新：项目集成层面的改进

1. 双存储证据链：Chroma 负责语义候选，MySQL 负责当前公开原文；检索后检查公开状态及内容摘要，使失效索引不能直接成为答案证据。
2. 三层引用约束：检索片段编号、模型自检、服务器精确引文匹配及可信元数据回填。把可回查性落实到章节，而不是仅在答案末尾列网页地址。
3. 低资源建库路径：云端向量化、1024 维表示、内容摘要幂等、容量规划与分阶段覆盖，避免本机模型占用，并用真实建库后截图约束容量表述。
4. 轻量追问检索：有限历史补足指代，与生成历史区分；不新增一轮模型改写请求，兼顾成本和语境。

## 14.2 应用创新：学习流程层面的改进

1. 阅读、讲解、引用核对和原句批注位于同一知识工作区，降低跨平台切换。
2. 学习程度与解释方式独立组合，允许用户本轮自然语言覆盖默认选择，使同一词条服务不同基础的读者。
3. 以来源章节为纽带连接 AI 答案和社区反馈，使错误能回到具体知识位置讨论。
4. 搜索不打断阅读，移动端分视图降低三栏界面的空间压力。

## 14.3 创新声明边界

以上是本项目的工程与应用组合特点，不主张发明 RAG、向量数据库、链式验证或获得算法层面的首创。没有训练专属数学模型，也没有形式化证明器；尚未有对照实验支持“显著提高成绩”之类结论。

# 15 总结、限制与展望

## 15.1 总结

项目实现了从公开数学词条到语义检索、分层解释、来源回查与社区讨论的可运行闭环。生产建库完成 48,560 段，在有限主机资源下形成了可观察的部署结果。仓库提供配置模板、依赖锁文件、测试入口与复现路径，支持评审独立查看代码。

## 15.2 当前限制

- 双阶段生成增加总等待，最终答案可能与流式初稿不同；应继续改善状态提示与重排体验。
- 规则识别追问无法完整解析所有指代；检索阈值与证据排序尚缺标准问题集校准。
- 模型自检并非独立事实裁判，存在相关错误；引文存在不等于结论正确。
- 超长章节尾部未全部建库；复杂模板和外链图片存在解析及可用性限制。
- 会话刷新恢复、长期画像与共享配额尚待完善；HTTP 部署与并发峰值验证仍是上线边界。

## 15.3 优先级路线

近期：部署本轮保护，验收不同程度与追问；建立 30 题人工标注集，分开记录检索、初稿、自检耗时。中期：优化查询相关性、对话恢复、移动端真机兼容，建立内容更新后的过期向量清理流程。后续：在具备明确需求和资源后引入重排序、混合检索或更完善的权限过滤。

语音输入与 Elasticsearch 在资源和 HTTPS 条件满足后再评估，不能为凑技术路线强行启用。每个新增组件应证明可衡量收益，而不是只增加架构图中的方框。
