# 追问检索与读者程度更新

## 行为变化

- 本轮明确提出的程度、篇幅、难度和解释方式优先于下拉框默认选择。事实及引用规则不受影响。生成和核验均收到同样的优先级要求；同步接口核验也保留用户原问题。
- 小学生讲解先给具体情景，用短句，术语需要日常解释；核验也检查标题、摘要、正文是否过难。实际语言质量仍需要真实模型验收，自动测试不代表模型一定遵守。
- 流式对话中的“第二步为什么”“它是什么意思”“没听懂，再简单些”等追问，在检索输入中带上最近两轮用户问题（各最多 400 字）和上一轮回答（最多 1600 字）。不额外调用模型改写问题。
- 指代识别使用规则，不是完整语义理解。独立问题默认不附带历史，避免旧话题干扰；复杂指代可以直接写出具体主题。历史只用于定位问题，不作为答案证据，引用仍须匹配当前公开原文。

本次不修改切分、模型、向量维度或集合，现有 48,560 段索引继续使用。无须重跑建库、修改 `.env` 或编译前端。

## 部署

使用 `mathwiki-conversation-rag-complete.zip`，包含同一提交的完整后端源码和依赖清单，避免服务器已有 `plan.go` 与旧版 `index.go` 混用。旧增量包不再用于部署。

将该完整包上传到服务器 `/opt`，执行：

```bash
(
set -e
unzip -o /opt/mathwiki-conversation-rag-complete.zip -d /opt
source /etc/profile.d/mathwiki-go.sh
cd /opt/mathwiki/backend
GOPROXY=https://goproxy.cn,direct GOMAXPROCS=1 GOMEMLIMIT=256MiB CGO_ENABLED=0 \
  go build -p 1 -trimpath -ldflags="-s -w" -o bin/mathwiki-server.new ./cmd/server
chmod 755 bin/mathwiki-server.new
mv -f bin/mathwiki-server.new bin/mathwiki-server
)
```

编译成功后，在宝塔 Supervisor 重启 `mathwiki`。这一步才会让运行中的后端使用新代码。

如果遇到 `c.index undefined`，说明编译目录内的 RAG 源码版本不一致，并非向量数据损坏。解压上述完整包后重新编译即可。不删除服务器现有源码目录、配置、二进制或数据卷；包内不包含 `.env`、数据库、向量数据或 `backend/bin`。构建失败时 `set -e` 会在替换原程序之前退出，不要提前重启服务。

## 网页验收

1. 下拉框选择“本科生”，在微分对策词条提问“我是小学生，请用简单的短句解释”。应先出现追逐等具体情景，避免直接堆叠专业定义。
2. 再提问“请按专业学习者的程度给出定义和前提”，应改变难度。核验后的最终版本仍需遵守本轮要求。
3. 归并排序词条先问“分步骤说明它怎样工作”，再问“第二步为什么这样做，举个例子”。展开引用，检查证据是否涉及对应的合并过程。
4. 同一对话再问一个明确的新问题，检查引用不被上轮关键词带偏。

检索到相关段落不保证每个问题都能回答；证据不足应仍如实说明，不降低相似度阈值或编造引用。
