# 条目审核、删除与纠错反馈

管理员右上角「审核管理」包含三个分类：

- **条目审核**：新建待审核、导入待核验、已通过、已驳回、回收站；支持标题搜索、完整正文预览、通过、驳回、删除、恢复。
- **批注审核**：待审核、已公开、已驳回；保留原有通过/驳回/删除能力，增加相关条目正文预览。
- **纠错反馈**：待处理、已处理、不采纳；显示提交者、相关条目、建议正文、时间和处理说明。处理说明必填，提交者可见。标记已处理**不会自动修改条目正文**，目前没有整篇条目的在线编辑器。

条目右上角「…」菜单和右侧「条目信息」面板都提供「审核此条目」「删除条目」（仅管理员可见）。
普通用户没有管理权限，不能通过直接调用接口绕过权限检查。

## 哪些内容会公开

- 新建条目先进入「新建待审核」，通过后才在公开知识库、搜索、分类中显示。
- 历史 `community_pending` 条目即使旧数据的 `published=true`，也会被公开查询过滤；内容没有删除，管理员可在待审核分类查到。
- 已有维基导入内容保留公开状态，单独进入「导入待核验」，不批量下架、不冒充人工审核通过。
- 驳回会隐藏条目。已驳回条目可再次通过；审核接口检查前端读取的原状态，避免过期页面覆盖其他管理员的处理。
- 搜索（含 Elasticsearch 命中后的 MySQL 校验）、正文、关联批注/回复/评论、收藏、阅读历史、解释和反馈接口均检查条目公开状态。

## 删除与恢复

删除采用 MySQL 软删除，正文、章节、讨论、收藏和反馈仍保留。公开接口无法读取被删条目及其讨论，公开计数同步排除它们。
管理员可在「审核管理 → 条目审核 → 回收站」恢复；恢复后沿用删除前的审核状态，未通过审核的内容仍不公开。
这不是彻底删除，也不会删除 COS 头像或其他对象存储文件。

## 纠错提交后在哪里看

在文章底部、条目「…」菜单或「条目信息」面板点击「提出补充 / 纠错」。
提交后：管理员在「审核管理 → 纠错反馈」处理，用户在左侧「我的反馈」查看自己的记录与回复。
每个账号只能读取自己的反馈；管理员可查看全部。原有反馈记录在新增状态字段后默认为待处理。
AI 解释的「有帮助 / 需改进」评价也在反馈列表中，类别不同。

## 验证

后端回归测试覆盖管理员权限、待审核隔离、通过/驳回、历史待审记录、删除后的各公开接口隔离、回收站恢复、关联讨论保留、反馈越权和处理结果可见性。
前端构建和标签测试覆盖中文状态展示。数据库迁移只增加反馈处理字段，不重新导入文章。
