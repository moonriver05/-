# 账户、评论与审核

## 使用

右上角「登录 / 注册」进入登录页。访客可以阅读文章、公开批注和文章评论。
注册后即登录，账号支持 3–40 位英文字母、数字、下划线，统一为小写；昵称支持中文。
新注册必须填写邮箱并通过 6 位验证码验证；一个邮箱只能注册一个账户。
密码至少 8 个字符，不超过 72 个 UTF-8 字节；密码只存储 bcrypt 哈希。

普通用户可以收藏、记录阅读、提交批注、回复公开批注、发表评论和反馈。
普通用户新批注状态为 pending，仅作者与管理员可见；管理员通过后为 visible，驳回为 rejected。
文章底部评论和公开批注下的回复即时发布，作者可删除自己的内容。
管理员拥有以上全部权限，另可通过「审核管理」审核批注、删除任何批注及评论、创建条目和分类。
批注删除同时软删除其回复。删除为数据库软删除，不提供前端恢复入口。

## 注册邮箱发信配置

在项目根目录 `.env` 填写以下配置（已预留空项），不要把授权码发到聊天或放进前端代码：

```dotenv
SMTP_HOST=你的邮箱服务商提供的SMTP服务器
SMTP_PORT=465
SMTP_TLS_MODE=tls
SMTP_USERNAME=完整发信邮箱地址
SMTP_PASSWORD=邮箱SMTP授权码或应用专用密码
SMTP_FROM=完整发信邮箱地址
```

通常 SMTP_USERNAME 与 SMTP_FROM 相同。按服务商要求启用 SMTP，并使用授权码/应用密码；
若服务商提供 587 端口，则设置 `SMTP_PORT=587`、`SMTP_TLS_MODE=starttls`。
仅支持认证并加密的 SMTP，不支持明文连接，不会跳过 TLS 证书验证。
SMTP_PASSWORD 可能不是网页登录密码，应遵循邮箱服务商说明。

修改后在项目根目录运行 `.\scripts\dev.ps1 -Restart`。Docker 部署需重新创建 API 容器以加载配置。
配置为空时注册页明确提示“发信服务尚未配置”，不会生成演示验证码，也不允许跳过验证注册；已有账户仍能登录。
尚未验证的历史账户保留登录权限，本次不强制补绑邮箱。没有忘记密码或换绑邮箱接口。

验证码 10 分钟过期，60 秒后可重发；同邮箱每小时最多发送 10 次，单个验证码最多尝试 5 次。
错误次数、重发冷却和邮箱限额存储在数据库，重启服务不会清零；重发成功后使用最新验证码。
验证码只存 bcrypt 哈希，不返回给前端、不写入日志；创建用户与消费验证码在同一事务内进行。
发送失败会使本次验证码失效，仍保留发送冷却和配额以避免连续重试轰炸邮箱。
邮件提示“发送成功”表示 SMTP 已接受，实际投递仍受服务商及垃圾邮件规则影响。

## 个人主页与头像

登录后点击右上角昵称/头像，即可修改昵称、简介、所在地和个人网站，并更换头像。
头像使用腾讯云 COS（公有读、私有写）；配置、安全边界和流量说明见 [个人主页与 COS 配置](profile-cos.md)。

## 设置管理员

不设置默认账号或默认密码，注册请求不能指定角色。先通过网页注册自己的账户，
然后在项目根目录 PowerShell 运行（将 your_account 替换为注册的账号，不是昵称）：

```powershell
.\scripts\set-user-role.ps1 -Username your_account -Role admin
```

刷新网页即可显示「审核管理」。取消管理员权限：

```powershell
.\scripts\set-user-role.ps1 -Username your_account -Role learner
```

脚本读取根目录 `.env` 的数据库配置，不输出密码。不要将脚本或数据库权限开放给网站用户。
已有演示用户保留历史记录，Username 为 NULL、无可用密码，不允许用演示身份登录；
旧收藏与批注不会擅自分配给新用户。迁移只新增字段和表，不重新导入文章。

## 会话与部署

- 采用数据库会话，随机 256 位 Cookie，数据库只存 SHA-256 摘要，有效期 7 天；退出后立即撤销。
- Cookie 为 HttpOnly、SameSite=Strict。正式 HTTPS 部署必须设置 `AUTH_COOKIE_SECURE=true`。
- 前端通过同源 `/api` 访问；Vite 开发代理和 Nginx 均适用。不允许任意跨域凭据访问。
- 写请求必须包含 `X-MathWiki-Request: 1`，不接受跨域表单写入；不要添加宽泛 CORS 放行规则。
- 注册、登录和发送验证码共享直接连接 IP 限制，每 15 分钟 20 次。反向代理场景可能共享额度；正式部署应在可信网关设置真实客户端限流，再调整后端策略，不可直接信任任意 X-Forwarded-For。
- 管理员身份每个请求都从数据库读取，不能通过客户端改角色绕过。
- 当前未实现忘记密码、换绑邮箱、封禁用户、审核理由及完整管理员操作审计。
- AI 和语音服务仍需要其原有云服务配置，注册账户不会使尚未配置的云服务自动可用。

## 验证

条目审核、删除/恢复和纠错反馈入口见 [内容审核说明](content-moderation.md)。

后端 `go test ./...` 覆盖注册角色注入、密码错误、重复账号、会话过期/注销、跨用户收藏/阅读隔离、
待审核内容可见性、审核权限、删除权限、文章评论和 CSRF 校验。
邮箱测试覆盖缺失/错误/过期验证码、错误尝试上限、重发冷却、邮箱发送限额、单次消费、邮箱不匹配和发信失败。
测试使用内存替代发信器，不向真实邮箱发信；真实 SMTP 投递需填入配置后另外联调。
前端 `corepack pnpm --dir frontend build`、`corepack pnpm --dir frontend test`。
